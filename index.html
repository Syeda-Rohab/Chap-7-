Leaving the Laptop: A Runtime Crash Course

Chapter Explanation — Roman Urdu (Bohat Aasan Version)

Shuruaat

Intro:

Aapne ek acha loop banaya — subah khud chalta hai, harness khatarnak kaamon ko rokta hai, eval suite number deta hai jise defend kar sakte hain. Sab kuch sahi kiya, lekin sab kuch rukta hai jese hi aap laptop band karte hain, WiFi chala jata hai, ya flight mein baithte hain. Aapke sabse bharosemand worker ka ek hi masla bacha hai: wo machine jo aapki desk par hai. Ye chapter sikhata hai: aapka loop kahan rahe, aur usay zinda kaun rakhe — ye "runtime decision" hai.

Zaroori Alfaz:

Runtime = wo computer aur software jo aapke agent ko chalata hai. Home = runtime ka choice: session, cloud schedule, managed runtime, apna process. Control plane = loop ka wo hissa jo chalata hai. Execution plane = jahan asal kaam hota hai. Custody = kiske paas data hota hai. Headless = agent ko sirf command se chalana. Managed runtime = ek service jahan aap definition bhejte hain, wo isay chalate hain. Portability = kitna hissa nayi jagah bina rebuild kiye chal jata hai. Lock-in = kisi jagah se nikalne ka kharcha. Blast radius = agar bura raat ho to kitna nuksaan. Pager = wo alarm jo raat ko engineer ko jagata hai.

Part 1: Aakhri Masla

Concept 1 (Laptop par proven loop ek bura rakha hua khazana hai):

Aapne 3 courses mein jo banaya usay gino: ek loop jo triage karta hai, ek harness jo khatarnak galtiyan naa-mumkin banati hai, aur ek eval suite jo defend karne layak number deta hai — ye lagbhag ek junior colleague jaisa hai. Ab dekho kis par ye depend karta hai: laptop khula ho, session login ho, machine subah 9 baje jaagi ho, power aur internet ho. Koi ek miss ho to beat chup chaap nahi chalti. Aasan misaal: aapne ek acha worker train kiya, lekin sirf apne living room mein, sirf jab aap ghar par ho, kaam karne ki condition rakh di. Worker theek hai, arrangement masla hai.

Concept 2 (Ek sawal jo sab kuch sort kar deta hai):

"Loop kaun operate karta hai, aur kaam kahan execute hota hai?" 2 hisse: Control plane (loop khud) aur Execution plane (jahan kaam hota hai). Laptop par ye dono ek hi machine hain, is liye aapko farak kabhi nahi dikha.

4 Homes: Session, Cloud schedule, Managed runtime, Apna process — ownership barhta jata hai

4 Homes (Ghar):

1) Aapki session — sab kuch aap khud rakhte hain. Yahin banana/prove karna theek hai, depend karna galat. 2) Cloud schedule — config aapki rehti hai, sirf clock kisi aur ke computer par jata hai. 3) Managed runtime — aap agent ki definition dete hain, vendor loop chalata hai. 4) Apna process — harness ek library ban jati hai aapke apne software mein — ye "Mode 2" ka ilaka hai.

Part 2: Headless Ek Pul Hai

Concept 3 (Har ghar headless boli bolta hai):

Aapne pehle se ye pul cross kiya hai — eval course mein claude -p aur opencode run use kiya. Koi bhi cheez jo command chala sakti hai, ab aapka agent chala sakti hai — shell script, cron job, CI runner, cloud scheduler. Zaroori qaida: ab koi dekh nahi raha, is liye headless runs ko zor se bolna zaroori hai jab fail hon — khamoshi ka matlab hamesha "success" hona chahiye.

Concept 4 (Home 2 — Cloud schedule, pehla kadam):

Sirf clock badalta hai, config wahi rehti hai. Claude Code: /schedule command se ek Routine banti hai jo Anthropic ke cloud par chalti hai. 3 honest baatein: Routines abhi research preview mein hain, waqt "around" hota hai exact nahi, aur green status ka matlab sirf ye hai ke technical error nahi aaya, task sahi hua ye nahi. Success ki definition: kam se kam ek pura cycle aur 10 successful beats, laptop band, khamoshi ka matlab baseline.

Minimum Unattended Kit (6 zaroori cheezein):

1) Idempotency — dobara chalane se nuksaan na ho. 2) Missed-run detection — agar run hui hi nahi to koi doosri cheez notice kare. 3) Concurrency lock — ek waqt mein ek hi beat chale. 4) Credential discipline — scoped credentials, personal login nahi. 5) Time semantics — timezone, daylight saving pehle se decide. 6) Cost/execution limits — max duration, retries, spend.

Part 3: Managed Runtime

Concept 5 (Aap definition bhejte hain, service worker chalata hai):

Managed runtime ek service hai — aap agent describe karte hain (model, prompt, tools, guardrails), service isay operate karti hai. Loop, session state, crash recovery — sab vendor ki taraf. Misaal (Claude Managed Agents) 3 cheezein banati hain: Agent (definition), Environment (walled space), Session (ek jaari kaam). 2 zaroori facts: managed control plane vendor-specific hota hai, aur managed runtime aur SDK alag products hain.

Concept 6 (Kya milta hai, kya dena parta hai, kya lagta hai):

Milta hai: operations ki fikr khatam — sandboxing, session recovery. Infrastructure pager unka. Dena parta hai: Visibility (sirf event log dekhte ho), Custody (data unki infra par execute hota hai), Portability (definition unke format mein hai). Cost: naya bill type — runtime khud metered hota hai (active session ke hisab se, idle free). Jitna loop bhatakta hai, utna paisa lagta hai.

Part 4: Move Karna

Concept 7 (Suitcase test — discipline jati hai, mechanics nahi):

Jo suitcase mein jaata hai: Spec (kya karna hai), rubric, golden set aur baselines, ratchet log, maker-checker split, human gate — ye sab decisions hain, software nahi, isi liye jati hain. Jo peeche reh jata hai: Flags, file paths, session state, ek vendor ke API ke liye likha code, cost assumptions. Zaroori sentence: repo asal sach rakhta hai, aur har ghar usi se configure hota hai.

Concept 8 (Trust dobara kamana parta hai, transfer nahi hoti):

Aapka purana 35/36 score us poore system ka measurement tha. Move karne se ye sab badal gaya, is liye score automatically nahi aata. Arrival Protocol (4 steps): 1) Poora golden set naye ghar mein pehla kaam karke chalao. 2) Kaunsi category fail hui pehle dekho, sirf ginti nahi. 3) Bar wahi rakho, phir naya baseline record karo — purana baseline delete nahi hota. 4) Probation — kam se kam 10 successful beats, purana ghar available rakho, ek galti khud plant kar ke alarm test karo.

Part 5: Ghar Chunna

4 sawal — pehle 3 ghar chunte hain, chautha sirf speed limit set karta hai

Concept 9 (4 Sawal):

Sawal 1: User kaun hai? Sirf aap? To Home 2 kaafi hai. Doosre log bhi hain to loop ko aapke bina bhi chalna chahiye. Sawal 2: Kya zaroor apna hona chahiye? Kuch nahi → managed runtime theek hai. Sirf execution/data → managed + self-hosted sandbox. Control plane bhi → apna runtime (Mode 2). Sawal 3: Kya koi insaan jawab ka wait kar raha hai? Scheduled/background → schedules/managed sessions kaafi. Insaan screen par wait → serving runtime chahiye. Sawal 4: Bura raat kitna mehnga hoga? Kam nuksaan → jaldi move karo. Bara nuksaan → poora suite pass hona chahiye pehle.

Concept 10 (Ek poori misaal, aur ghar mix karna):

Ayesha ki invoicing loop 5 clients ko serve karti hai, ek bank hai jise data khud ke infra par rakhna zaroori hai. Sawal 2 ka jawab: bank ka "must" execution/data plane ke baare mein hai — Home 3 with self-hosted sandbox theek ho sakta hai. Zaroori baat: ek system usually 2-3 ghar mix karta hai — roz ka loop Home 2 mein, bara one-off kaam Home 1 mein interactively. Repo asal sach rakhta hai — yehi cheez mix ko organized rakhti hai.

Part 6: Honest Rehna

Concept 11 (Lock-in ek rate hai, aur ownership chupke se ghisti hai):

Lock-in ek waqia nahi, ek rate hai. Koi ek din portability nahi chorta — chhota chhota leak hota hai. Har quarter check karo: "Agar ye ghar gayab ho jaye, isay dobara banane mein kitna kharcha hoga?" Ownership bhi chupke se ghisti hai — jab system mahino chupchap chalta rahe, aap khud check karna band kar dete hain. Fix: calendar reminder lagao, khud check karte raho.

Concept 12 (Ghar kya theek nahi kar sakta):

Behtar ghar sirf kab agent kaam karta hai, kaun usay zinda rakhta hai, aur raat 3 baje kya hota hai — isay change karta hai. Ye ek cheez change nahi karta: agent kitna acha kaam karta hai. Kamzor spec Anthropic ke cloud par bhi kamzor rahega. Poore section ka safar: aapne agent chalana seekha, phir spec se direct karna, phir loop delegate karna, harness sakht karna, checker naapna, aur ab poore system ko ghar dena — ye poori cheez ka naam hai: Digital FTE. Aakhri jumla: loop ne agent ko waqt diya, harness ne limits diye, evals ne track record diya. Ye chapter ne aakhri cheez di: ek address jo aapki nahi hai.

End Summary (Aik Nazar Mein)

  • Laptop par proven loop ek "bura rakha khazana" hai — machine khud sabse bara single point of failure hai
  • Zaroori sawal: loop kaun operate karta hai, kaam kahan execute hota hai?
  • 4 Homes: Aapki session, Cloud schedule, Managed runtime, Apna process
  • Headless har ghar ka pul hai — koi bhi command chala sakti hai to agent kahin bhi chal sakta hai
  • Home 2 (schedule): sirf clock badalta hai — 6 zaroori controls (idempotency, missed-run detection, waghera)
  • Home 3 (managed): definition bhejte ho, vendor operate karta hai — visibility/custody/portability dena parta hai
  • Suitcase test: decisions (spec, rubric, golden set) jati hain, mechanics (flags, paths) nahi jati
  • Move karne ke baad trust dobara kamani parti hai — poora suite chalao, naya baseline banao, probation do
  • 4 sawal ghar chunte hain: user kaun, kya apna hona chahiye, kya insaan wait kar raha, bura raat kitna mehnga
  • Lock-in ek rate hai, waqia nahi — repo mein sach rakho taake kabhi bhi nikal sako
  • Ghar sirf "kab aur kaun" change karta hai, "kitna acha" nahi — quality spec/harness/evals se aati hai
